# 已确认决策

来源：用户在本会话的明确答复及v1.4需求基线。产品规则优先于候选技术建议。

- client/server顶层，Tauri2/React/TypeScript、FastAPI和PostgreSQL。后端采用controller/service/repository/entity/domain分层，DO、DTO、QO、VO分别建文件，业务服务类与文件带Service用途后缀。
- 桌面界面采用浅色黑白灰，少量蓝色强调；用户已否定原灰绿色主题。导航、表单与状态保持统一，设计来源见ui-design-references.md。
- Python后端使用uv管理项目：server/pyproject.toml、uv.lock、.python-version、uv维护的.venv；前端包命令继续用pnpm。
- 单管理员账号密码，多设备同一账号，各设备独立安全会话，无注册/多用户权限。用户确认管理员密码可用6位纯数字；软件允许6至128个字符，不强制字母/符号。
- 后端与React/Tauri客户端独立启动。可在PyCharm中分别配置运行入口，也可由PyCharm与VS Code分别运行。服务部署这台Mac的OrbStack，允许LAN Mac Intel、Apple Silicon Mac及Windows客户端，系统版本、Windows架构和构建机按实际设备验证。
- 日常记录订单、收货、退货；到货=初始接受+问题/待处理，问题货支持部分转接受/退回/换货。
- 每笔纳入订单义务的退货选择补交/减量。原订单量保留，应交与净接受分别计算。
- 真实超收可登记，超出部分待处理；接受前需订单变更。未纳入义务的超收退回不生成补交或减量。
- 数量与单价最多6位；税率百分数最多4位；金额2位，ROUND_HALF_UP，按录入含税/未税口径逐行舍入再汇总。
- 对账默认自然月，可自选区间；收退货用业务发生日期；迟到补录保留真实日期并通过后续调整承接历史确认。
- 草稿可编辑；生效订单追加变更；收退货冲销重录，处理下游依赖；已确认账单/发票保持快照，新增调整。
- 对账、发票独立核对与额度；全部差异人工处理，接受差异必须说明理由并留痕。
- 输入.xlsx/.xls、PDF、PNG/JPG/JPEG，中英文，扫描PDF和图片属于一期；密码文件先解密。
- 一期使用联网模型API，允许发送待解析内容；真实供应商/API、预算及样本暂未准备。

待对应阶段落实的事项包括先补后退及订单关闭等复杂业务边界、设备版本和构建资源、真实模型与评测基线、备份留存以及完整发布验收。会话与TLS基础已有验证，2026年11月17日已完成稳定主机名、证书及HTTPS入口修复，当前Mac的主机名与IP备用入口均通过系统信任校验，其他设备名称解析和证书信任继续实机验收。

## 开发分工与验收约定

用户手写业务代码，助手先创建对应空文件，并在对话提供中文文档字符串和必要中文注释。助手完成公共适配、迁移、全部测试及用户授权的修复。各业务任务分别记录后端可联调、客户端可操作和综合验收，整项关闭条件见实施规划。

规划保留原任务编号，D08a纯计算供资料模块复用，D08b随第一张数量金额业务表验证PG往返。D09验收资料管理和独立选择组件，订单页面集成由D10验收。PDF/OCR、真实模型和三平台最小构建作为独立技术子项提前验证，最终一期范围继续完整验收。
